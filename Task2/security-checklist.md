# Проверочный лист бизнес-систем

Оценка текущей архитектуры по описанию кейса и исходной C4-схеме. «Нет данных» означает, что контроль нужно проверить, а не что он отсутствует. Решения Task3–Task5 здесь не считаются уже внедрёнными.

## Область проверки

| Системы | Что проверяем |
|---|---|
| Витрина продаж, client-tour-app, client-mart-app, client-mart-estate-app | Регистрация, бронирование, объекты, онлайн-сделки и взаимодействие с госорганами |
| client-crm-app, crm-db | Карточки покупателей, контакты и согласованность идентификаторов |
| Мобильное приложение, tenant-core-app, tenant-core-db, CRM собственников | Доступ к своему жилью, ЖКУ, платежам и устройствам |
| auth-service-1, auth-db-1, Active Directory | Идентификация и выдача/отзыв прав пользователей и сотрудников |
| accountant-service-1 и его БД | Финансовые операции, права бухгалтерии и целостность данных |
| Хранилище данных, DWH, BI и отчётность | CDC-потоки, минимизация данных, доступ к аналитике |
| API управляющих компаний и платёжной системы | Изоляция партнёров, состав передаваемых данных, контроль контрактов |

## Выбор разделов

1. **Управление доступом:** уже обнаружены доступ одной УК к данным другой и показ чужих данных в личном кабинете. Это первоочередной риск.
2. **Безопасность данных:** несколько точек регистрации и неконтролируемые потоки в DWH мешают безопасно развивать аналитику. Нужны единые идентификаторы, классификация, контроль качества и минимизация данных.
3. **Интеграции:** партнёрские API передают лишние персональные данные. Проверяются права на каждый объект, договоры и ограничения API.
4. **Инфраструктура:** компания использует собственный ЦОД, облако и Kubernetes. Один внешний firewall не подтверждает изоляцию внутренних систем или безопасную настройку кластеров.
5. **Аудит и процессы:** специалисту ИБ сообщают не обо всех изменениях. Нужно восстановить согласование интеграций и обеспечить расследование инцидентов.

## Проверки

| № | Вопрос | Да / нет | Комментарий |
|---|---|---|---|
| **I** | **Управление доступом** | | |
| I.1 | Используются ли сервисы аутентификации? | Да | На схеме есть auth-service-1 и Active Directory. Настройки и качество реализации требуют проверки. |
| I.2 | Применяется ли MFA для критических систем и администраторов? | Нет данных | Проверить политики AD, auth-service-1 и доступ к Kubernetes. |
| I.3 | Проверяются ли права на каждого клиента, дом и УК? | Нет | Описан просмотр и изменение данных другой УК. Проверить object-level authorization и отрицательные тесты. |
| I.4 | Исключён ли показ чужих данных в личном кабинете? | Нет | Есть жалобы на чужое Ф. И. О. Проверить идентификаторы, фильтры, кеширование и привязку сессий. |
| I.5 | Есть ли единый реестр клиентов и правила сопоставления идентификаторов? | Нет | Несколько точек регистрации не координируются. Нужны проверки дублей и межсистемных связей. |
| I.6 | Пересматриваются ли права и отзываются ли они при увольнении или смене роли? | Нет данных | Запросить регламенты, выгрузки прав и примеры отзыва доступа. |
| I.7 | Разграничены ли права Kubernetes по группам и доменам? | Нет данных | Проверить Role/ClusterRole и привязки, включая Secrets и привилегированные операции. |
| **II** | **Безопасность данных** | | |
| II.1 | Утверждена ли классификация данных и назначены ли владельцы? | Нет данных | Запросить классификатор и ответственных за данные четырёх доменов. |
| II.2 | Контролируются ли внутренние потоки и доступ из DWH/BI? | Нет | По кейсу системного контроля потоков и ограничений со стороны обработки данных нет. |
| II.3 | Проверяются ли точность и согласованность клиентских данных? | Нет | Показ чужих данных говорит о недостаточности текущих проверок. |
| II.4 | Шифруются ли данные при передаче и хранении? | Нет данных | Проверить TLS, БД, диски, логи и резервные копии; firewall этого не доказывает. |
| II.5 | Защищены ли ключи, пароли и токены, настроена ли ротация? | Нет данных | Проверить хранилище секретов и порядок замены ключей. |
| II.6 | Выполняется ли резервное копирование всех БД? | Да | Это указано в описании. Глубину хранения сопоставить с RPO/RTO бизнес-систем. |
| II.7 | Проверяется ли восстановление, защищены ли резервные копии? | Нет данных | Запросить протокол восстановления и настройки шифрования/доступа к копиям. |
| II.8 | Определены ли цели, основания и сроки обработки персональных данных? | Нет данных | Проверить реестр обработки, договоры, согласия и порядок удаления/исправления данных. |
| II.9 | Минимизируются или обезличиваются ли данные для BI/ML? | Нет данных | На схеме передача сырых данных по CDC. Проверить состав полей; CDC не доказывает обезличивание. |
| **III** | **Внешние интеграции** | | |
| III.1 | Есть ли единая политика безопасности партнёрских API? | Нет | В кейсе указано отсутствие единых политик и контроля передаваемых данных. |
| III.2 | Ограничен ли контракт минимально необходимыми данными? | Нет | В контрактах обнаружены избыточные категории персональных данных. |
| III.3 | Изолирован ли каждый партнёр своей УК и набором объектов? | Нет | Партнёр может видеть или изменять объекты другой УК. Проверить tenant-scoping на сервере. |
| III.4 | Проверяются ли токены, scopes, срок действия и отзыв доступа? | Нет данных | Изучить аутентификацию API и управление учётными данными, провести негативные тесты. |
| III.5 | Защищены ли callbacks от подделки и повторной доставки? | Нет данных | Проверить mTLS, timestamp, идентификаторы событий и дедупликацию. |
| III.6 | Есть ли договоры обработки, проверка размещения и субподрядчиков? | Нет данных | Запросить документы по УК, платежам и будущему биометрическому партнёру. |
| **IV** | **Защита инфраструктуры** | | |
| IV.1 | Ограничен ли внешний доступ межсетевым экраном? | Да | Вход клиентов и собственников осуществляется через firewall. Исходящие правила не описаны. |
| IV.2 | Изолированы ли внутренние домены и административные интерфейсы? | Нет данных | Проверить сегменты ЦОД/облака, NetworkPolicy, VPN и маршруты к БД. |
| IV.3 | Сканируются ли приложения, образы и инфраструктура на уязвимости? | Нет данных | Запросить результаты сканирования и процесс обновлений. |
| IV.4 | Контролируются ли настройки и права облачных ресурсов? | Нет данных | Проверить IAM, публичность хранилищ и ответственность провайдера. |
| IV.5 | Защищены ли физический доступ и оборудование ЦОД? | Нет данных | Запросить СКУД, учёт оборудования и порядок безопасной утилизации. |
| IV.6 | Защищены ли мобильный и удалённый доступ? | Нет данных | Проверить хранение сессий и доступ сотрудников; MDM для клиентских телефонов не предполагается. |
| **V** | **Аудит и управление изменениями** | | |
| V.1 | Согласуются ли все значимые изменения со специалистом ИБ? | Нет | После смены руководителей ему передают не все решения и изменения. |
| V.2 | Журналируются ли доступ, выдача прав и действия партнёров? | Нет данных | Проверить идентификаторы пользователя/УК/объекта, результат и correlation ID без чувствительного payload. |
| V.3 | Защищены ли журналы от изменения и утечек, определён ли срок хранения? | Нет данных | Проверить доступ, маскирование, сроки хранения и контроль целостности. |
| V.4 | Настроены ли мониторинг, уведомления и реагирование на инциденты? | Нет данных | Проверить обнаружение межклиентского доступа и эскалацию специалисту ИБ. |
| V.5 | Проводятся ли регулярные аудиты и обучение? | Нет данных | Комплексный аудит планируется. Запросить прошлые отчёты и результаты обучения. |

Сначала устранить межклиентский/межпартнёрский доступ и смешение профилей, затем ограничить потоки данных и восстановить контроль изменений. По пунктам «Нет данных» собрать подтверждения у владельцев систем.
